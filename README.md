# Signal K App Launcher

A start page for your phone: one bookmark (or home screen icon) that opens the
Signal K webapps and the other apps on your boat server, in the order you
choose.

- Add Signal K webapps from a list of what is installed on the server.
- Add any other app by URL, for example Grafana, Home Assistant or a router
  page.
- Arrange the tiles by hand.
- Laid out for phones, including the notch and gesture bar.

> Status: early development, not yet tested against a real Signal K server.

## Editing

Admins see an **Edit** link below the tiles. In edit mode:

- **+ Signal K app** lists the installed webapps that are not on the list yet.
- **+ Other app** adds anything else by name and URL.
- ↑ ↓ change the order, ✎ edits name, URL, tab, icon and tile colour, ✕ removes.
- **Name** sets the page title and the name a phone uses when you add the
  launcher to the home screen. Left empty, it is the vessel name (Signal K
  path `name`), or "Apps" when there is none. A launcher already on the home
  screen may keep its old name until it is added again.
- **Save** stores the list for everyone; **Cancel** discards the changes.

## Requirements

- Signal K server **2.35** or newer. Older servers run the plugin, but only
  admins can see the list.
- To use the start page without logging in, enable **Allow Readonly Access**
  under *Security → Settings*. Without it, log in once on the phone.

## Use

1. Install *signalk-app-launcher* from the App Store and enable it.
2. Open `/signalk-app-launcher/` on your server, e.g.
   `https://<your-server>/signalk-app-launcher/`.
3. Save it as a bookmark, or use *Add to Home Screen* (Safari) / *Install app*
   (Chrome).

### URLs of other apps

An app outside Signal K can be given as

| Form | Example | Opens |
|---|---|---|
| absolute URL | `https://example.org/` | exactly that |
| path on the Signal K server | `/grafana/` | same host and port as the launcher |
| URL with `{host}` | `http://{host}:3001/` | the host name you opened the launcher with |

`{host}` lets one entry work whether the phone reaches the server by name or by
IP address.

### Opening apps

Each app opens in one of three ways:

| Setting | Behaviour |
|---|---|
| Same tab | replaces the launcher; Back returns to it |
| New tab | a fresh tab every time |
| Own tab, kept open | one tab per app; tapping the tile again brings that tab back instead of reloading the app, as long as the browser keeps it |

"Own tab, kept open" needs the browser to allow the launcher to open windows.
Phones may still close background tabs to save memory; the app then loads
again on the next tap.

## Who may do what

| Action | Who |
|---|---|
| Open the start page and see the apps | anyone with read access (anonymous with *Allow Readonly Access*) |
| Change the list | admins |

The list is stored as `apps.json` in the plugin's data directory, so it
survives plugin updates.

## API

| Method | Path | Access | |
|---|---|---|---|
| `GET` | `/plugins/signalk-app-launcher/apps` | read-only | the app list |
| `PUT` | `/plugins/signalk-app-launcher/apps` | admin | replace the app list |
| `GET` | `/plugins/signalk-app-launcher/manifest.webmanifest` | read-only | web app manifest named after the title or vessel |

## Development

```bash
npm install
npm run typecheck
npm test
npm run build
```

`npm run build` compiles the plugin to `dist/` and the webapp to `public/`.
The icons in `static/` are generated by `node scripts/make-icons.mjs`.

To try the webapp without a server, `npx vite --config vite.mock.config.ts`
serves it at `http://127.0.0.1:5175/signalk-app-launcher/` with a fake Signal K
server behind it. The cookie `mock-level=admin|readonly|denied` sets what the
fake server allows.

Commits follow [Conventional Commits](https://www.conventionalcommits.org/);
releases are made by release-please.
